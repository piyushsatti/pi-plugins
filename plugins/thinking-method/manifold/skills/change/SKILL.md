# Reconsider after change

Use this capability independently. First read the [shared application method](../../references/guide.md)
and [reference route and standing](../../references/index.md). Resolve links relative to this
SKILL.md, not the user's working directory. Use existing context before asking questions.
This capability supplies application assistance; it does not adopt requirements or implement
users' modeled systems.

## Starter prompt

> This source, requirement, arrangement, evidence or standard revision changed. Identify affected relationships and conclusions, retain their earlier basis, and propose the smallest useful update and handoff.

## Required context and references

A before/after source, change account or revision pair, plus any current model and prior assessment. If the old basis is unavailable, request it or mark the comparison limit. Read [identity/change](../../references/source/standard/ontology/identity-and-change.md), [records](../../references/source/standard/information-model/records-and-provenance.md), [fulfillment over time](../../references/source/standard/assessment/requirement-and-need-fulfillment.md#time-changed-evidence-and-need-fulfillment), and [baseline maintenance](../../references/source/standard/application/case-development-baseline.md#maintenance-and-change).

## Method

1. Identify the changed subject and old/new source or configuration, relevant times, reason, and any recorded authority and effective scope. Distinguish a proposal, adoption, correction of historical evidence and a later real-world change.
2. Preserve the earlier basis and conclusion. A Monday recovery does not meet Friday's deadline; new evidence of an on-time Friday event may instead revise a previously unknown historical judgment.
3. Trace direct and indirect dependents: interpretations, needs, requirements, conditional consumer choices, contribution rationales, arrangements, assessments, decisions and maps. Identify unaffected claims with reasons rather than declaring everything stale.
4. For each affected item, explain the invalidated assumption or changed condition, what remains supported and what requires clarification or reassessment. Do not apply a new criterion retroactively without explicitly labeling a new analysis.
5. For a changed standard, compare applicable provision and standing, not just package version. State adoption/compatibility choices; a new file or a changed label does not automatically grant authority or revise the case.
6. Propose focused changes and a next evidence/decision request. Append revisions only within authorized updates to the selected global space, preserving old ones. Update table and map together. Prepare a receiving contributor's handoff with the old and new basis, applicable references and unresolved choices.

## Outputs

Return an impact account with before/after references, affected and unaffected claims, preserved judgments, proposed updates and a [handoff](../../templates/handoff.md). Use [change template](../../templates/change.md); default to [modeler](../../references/roles/modeler.md).

## Uncertainty and stopping

Stop after the bounded dependency trace and proposed updates. Report incomplete source coverage and do not invent a complete change graph. If the authoritative prior basis or needed reference is missing, preserve dependent conclusions as unresolved while completing unaffected comparisons.

If a required reference is unavailable, follow the shared method's missing-reference
behavior: identify the affected claim and continue only the supported parts. Never invent
the rule or silently claim the unavailable revision was used.
